# Kumbuka Documentation

## Features

- Markdown-first documentation stored in `content/`.
- Static-site generation with the Kumbuka CLI.
- Theme-aware navigation, table of contents, and browser-side search.
- Build-time validation for documentation links and static routes.
- Automatic deployment to GitHub Pages from `main`.

## Repository ownership

Kumbuka is maintained as separate repositories with explicit ownership boundaries:

- [`kumbuka-me/kumbuka`](https://github.com/kumbuka-me/kumbuka) — PostgreSQL-backed server, web application, and reusable runtime packages.
- [`kumbuka-me/cli`](https://github.com/kumbuka-me/cli) — static-site builds, Git-friendly mirrors, and `.kumbukaplugins` project tooling.
- [`kumbuka-me/sdk`](https://github.com/kumbuka-me/sdk) — plugin manifest/package contract, WASI guest API, typed capability clients, and the `kumbuka-plugin` development CLI.
- [`kumbuka-me/plugins`](https://github.com/kumbuka-me/plugins) — first-party plugin source, releases, previews, and generated plugin documentation.
- [`kumbuka-me/docs`](https://github.com/kumbuka-me/docs) — installation, administration, user, architecture, and cross-repository documentation plus application screenshots.

## Requirements

- GNU Make
- `curl`
- Python 3 for local preview
- Node.js/npm for formatting and screenshot automation
- Go, Docker, and `zip` for screenshot generation

The pinned Kumbuka CLI and development helpers are downloaded automatically. Screenshot automation installs its Playwright dependency from this repository's `package-lock.json`.

## Build locally

```sh
make build
```

Run the same formatting and artifact checks used by CI with:

```sh
make check
```

The generated site is written to `site/`. Build, serve, and open it locally with:

```sh
make serve
```

The local site uses a persistent random port for the current checkout.

## Screenshots

Documentation screenshots are owned and generated by this repository from the same Markdown under `content/`; there is no second application fixture copy. The screenshot runner downloads the Kumbuka release pinned in the `Makefile`, starts a real temporary Kumbuka instance with PostgreSQL, creates the first administrator, imports the documentation, and captures the configured application views. It then installs the documented first-party plugin releases and imports their canonical preview Markdown from a `kumbuka-me/plugins` checkout so extension preview PNGs are captured by the real Kumbuka renderer as well. Run:

```sh
make screenshots
```

The runner installs Playwright's Chromium browser when needed and writes application screenshots under `assets/screenshots/` plus extension previews under `assets/plugins/<plugin>/preview.png`. Captures use a 2× device scale factor by default so the PNGs stay sharp on HiDPI displays. A sibling `../plugins` checkout is used by default; override `SCREENSHOT_PLUGINS_DIR` when it lives elsewhere. The **Documentation Screenshots** workflow checks out both Kumbuka and the first-party plugins and commits changed PNGs.

## Extension documentation

The plugins repository remains the source of `content/extensions/index.md`, `content/extensions/<plugin>.md`, plugin manifests, READMEs, and canonical `preview.md` fixtures. Edit those sources in `kumbuka-me/plugins`; its documentation workflow commits generated extension pages here. The published `assets/plugins/<plugin>/preview.png` files are regenerated by this repository's screenshot runner from those preview fixtures inside a real Kumbuka instance.

To refresh generated extension pages locally, run `make docs DOCS_DIR=../docs` from the sibling plugins checkout, then run `make screenshots` in this repository. Plugin-development guides remain maintained in `content/development/plugins/`. The machine-readable first-party update catalog remains `content/plugins/catalog.json` so the server can continue to fetch `/plugins/catalog.json`.
